01 — Project Control Panel

What it is

The Project Control Panel is the local hub for its current Blender2BabylonKit project. Each project runs its own Project Control Panel. The Project Control Panel does not select, create, or manage other projects. One Express server exposes a JSON REST API and (in development) Vite middleware for the React hub. The hub lets you:

  • See the current project and pick a development level
  • Start/stop the game's Vite dev server and open the runtime preview (including a direct jump into any .scene.json)
  • Start, stop, and copy Cursor config for bjs-mcp (shipped with the kit; runs against the current project)
  • List the assets a level's scene JSON references and reload each one from its workspace source (gui/, particles/, materials/, …) — update a single sidecar asset without re-exporting the whole level from Blender
  • Publish a web build to a destination folder (see 02 — Publishing)

Nothing in the Project Control Panel runs inside the game runtime. It only orchestrates processes and reads/writes files under game/.

Hub UI

Documentation panel

The documentation site ships with the kit as version-controlled HTML. View Docs opens /docs/ on the Project Control Panel host — the same Express server serves the static files. There is no build button. The site is authored in the kit repository (see Building the documentation) and committed before each release.

Docs are considered available when docs/index.html exists in the kit package or checkout.

Current project panel

On load, the hub calls GET /api/project and shows the fixed current project. It does not show a project selector. The server uses the single game/ workspace (optional B2BKIT_PROJECT=game). The b2bkit-project.json file supplies the display title, entry level, dev port, and Blender Live Link path.

When game/ is missing, the hub can show Create Project (disabled once b2bkit-project.json is present). Prefer copying the game/ template or following Create a game with the published kit for outsider projects.

Services panel

Polls GET /api/services/:app every three seconds.

Game Dev Server (Vite) — Start runs npm run dev --workspace game from the project root. The Project Control Panel tracks the process and checks the configured port. A port that is open but does not serve this project (a stale Vite from an old folder layout, or another project's server) reports as busy · not this project with the offending pid, rather than a false "running". Both the kit and starter games set strictPort, so a collision fails loudly instead of drifting to the next port. Stop sends SIGTERM to the process group. On Linux, it also releases the port if necessary. Preview opens b2bkit-project.json.entryLevel through the ?manifest= query. Select a manifest and click Set as Entry to change this setting. The Publish tab uses the same entry level. The Open Level action opens any selected level without a rebuild. The selected manifest also controls the Assets panel.

bjs-mcp (Behavior Authoring) — the kit package ships a prebuilt copy, so Start launches it directly (node …/@bjs/engine/mcp/dist/index.js) with the current project as its working directory. It reads that project's game/src/behaviors/, levels, and Input Actions, and answers documentation queries from the packaged docs. A Build button appears only inside the kit checkout, where the TypeScript sources exist. Copy Cursor Config writes the stdio MCP snippet for bjs-level-kit (command, args, cwd) to the clipboard — paste into ~/.cursor/mcp.json. From a shell you can also run npx b2bkit-mcp in the project root.

Start All Services / Stop All Services call the combined endpoints that run dev + MCP in parallel.

Assets panel

The panel lists the assets the selected level's scene JSON references, grouped by folder — not a raw directory listing. The list comes from GET /api/projects/:app/assets/:level/references, which walks the level's .scene.json for manifest-relative paths (gui/hud.json, particles/bubbles.json, materials/water.json, …). Because it reads the deployed manifest, it always matches what actually ships in the level.

Each row has a Reload button. Reload recopies the matching source from game/workspace/<folder>/<file> over the deployed copy under game/public/levels/<level>/<folder>/<file> (POST /api/projects/:app/assets/:level/reload with { reference }). This is the update-one-asset-without-a-full-Blender-re-export path: edit a GUI / particle / material JSON in its Babylon editor, save it into game/workspace/, then Reload to push just that file into the level. Vite's level watcher then triggers a full page reload of the running game.

Reload is disabled when no matching game/workspace/ source exists (the row shows No workspace source) — the panel never invents a source or edits the workspace copy, so the Blender-authored asset cannot drift out of sync. A transient Reloaded confirmation appears after a successful copy and clears after a couple of seconds. The panel does not otherwise edit files; the raw PUT write route remains for tooling built on top.

Level roots and asset folders

Asset paths resolve through WorkspaceAssetRoot() in server/paths.ts:

Level selectorFilesystem root
_workspacegame/workspace/
<level name>game/public/levels/<level>/

Workspace (game/workspace/, moved out of public/ so it is not served as a runtime asset) is the pre-export staging area for sidecar JSON assets. It is not a playable level. Blender export copies each authored asset from here into the exported level folder; the Assets panel Reload button performs that same workspace → level copy for one file on demand. The current UI no longer shows Workspace as a selectable level because Services always selects an exported level, but the _workspace API value still resolves to game/workspace/ for tooling and pre-export workflows.

Under each root, these subfolders are scanned (constants in ASSET_FOLDERS):

FolderTypical content
gui/GUI editor JSON
particles/Node particle system sets (.json; image files such as .png can sit beside them but are not listed in the Project Control Panel)
materials/Node material graphs
geometry/Node geometry graphs
filters/Smart filter graphs
render-graphs/Node render graph JSON

Only .json files are listed. WriteAsset rejects non-.json names. Filenames and folder segments are sanitized; resolved paths must stay inside the level root (IsPathInside).

These folders sit beside the exported level.glb and level.scene.json for a level — they are not embedded in the glTF export. The runtime loads them when your game code or manifest references them.

REST API

All routes are under /api. Errors return JSON { "error": "message" } with an appropriate status code.

Assets

MethodPathDescription
GET/api/projects/:app/assets/:levelAll folders → filename arrays (raw directory listing)
GET/api/projects/:app/assets/:level?folder=guiSingle folder listing
GET/api/projects/:app/assets/:level/referencesAssets referenced by the level's .scene.json → ReferencedAsset[] (drives the Assets panel)
POST/api/projects/:app/assets/:level/reloadRecopy one referenced asset from workspace over the level copy; body { reference } → ReferencedAsset
GET/api/projects/:app/assets/:level/:folder/:fileRaw JSON file body
PUT/api/projects/:app/assets/:level/:folder/:fileWrite JSON; body string or object → { path, relative }

:level is the level folder name or _workspace. ReferencedAsset: reference (manifest-relative path, e.g. gui/hud.json), folder, file, sourceAvailable (a game/workspace/ copy exists), deployedAvailable (the level copy exists). Reload requires sourceAvailable and that the reference actually appears in a level manifest; it never writes back to the workspace.

Typical workflow

  1. Export from Blender — point Live Link at

game/public/levels/<level>/ (path shown in the hub).

  1. Start services — in the Project Control Panel, Start All Services (or start dev

only if you do not need MCP).

  1. Open runtime preview — follow the Vite link; Live Link re-exports trigger

a full reload via the app's Vite plugin (Workflow).

  1. Author behaviors — with MCP running, use Cursor and the bjs-level-kit

tools; paste MCP config once per machine.

  1. Drop sidecar JSON — save editor exports into the matching asset folder

under the level (or game/workspace/) and confirm they appear in the Assets panel.

  1. Reload one asset — after editing a GUI / particle / material JSON in

game/workspace/, click Reload on its Assets-panel row to copy just that file into the level and hot-reload the running game — no full Blender re-export.

Environment and troubleshooting

VariableDefaultEffect
CONTROL_PANEL_PORT3200Hub listen port

If port 3200 is in use, the dev server prints a hint to free it (fuser -k 3200/tcp on Linux) or set CONTROL_PANEL_PORT=3201.

Dev-server stop uses fuser on Linux only; on Windows, stopping relies on process signals to the spawned child.

In the kit monorepo the Project Control Panel runs from a full checkout (game/, scripts/, tools/). Published installs expose the same hub via npx b2bkit-control-panel from a project root that contains game/. The published kit bundles the compiled panel, a prebuilt bjs-mcp with its search index, and the versioned docs site, so services and docs work the same in both places. The one difference: the MCP Build button and the docs build are checkout-only, because those regenerate from sources that a normal install does not carry.
