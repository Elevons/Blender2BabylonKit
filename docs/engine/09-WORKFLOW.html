09 — Workflow & Tooling

Prefabs <a name="prefabs"></a>

Reuse authored props and characters by linking other .blend files into the level scene. Apply Blender library overrides per instance (transform, components, colliders, @exposed values).

The level file is what you export. Prefab libraries are maintained separately. Live Link runs on the level save. After editing a library file, save the level to push changes into public/levels/….

See Blender — Prefabs.

Live Link <a name="live-link"></a>

The save-to-see loop. Export once. The operator remembers the path per scene. Tick Live Link in Babylon Scene › Export. Every Ctrl+S re-exports (export/live_link.py, a save_post handler). There are no timers or sockets. Failures never break the save.

On the runtime side, the Vite plugin ReloadOnLevelExport (game/vite.config.ts) watches all files under public/levels/ (glb, env/, audio, manifest, …). It sends a 50ms debounced full reload. It is not only .scene.json. A replaced environment image still refreshes when the manifest bytes are unchanged.

IsLevelAsset resolves paths with path.resolve. Chokidar may report relative paths (public/levels/...) without a leading slash.

Re-exports are idempotent for side files. export_level calls begin_asset_export() (export/assets.py). Each save overwrites env/<name>.hdr, audio/…, and similar paths. It does not accumulate _2, _3, … copies when the manifest path is unchanged.

Object visibility <a name="visibility"></a>

Blender outliner has two independent toggles:

IconPropertyIn the exported level
Eyehide_viewportPresent but starts invisible (bjs_visible: false in glTF extras → node.isVisible = false at load)
Collider › Make Invisiblecollider_make_invisiblePresent and visible in Blender. Loads with node.isVisible = false when any enabled collider has makeInvisible: true. Physics is unchanged.
Ray Visibility › Shadowvisible_shadowPresent and visible. Still receives shadows but does not cast (bjs_cast_shadows: 0 → omitted from ShadowGenerator casters). Overridden when a Mesh Shadows component is enabled on the entity.
Mesh Shadows componentmesh_shadow_modeManifest MESH_SHADOWS row. When enabled, overrides ray visibility: Cast & Receive, Receive Only, Cast Only, or None on owned meshes (optional child propagation).
Camerahide_renderAbsent. Skipped by _is_renderable in export and use_renderable=True on the glTF exporter.

Use render-disable for editor-only objects that should never ship. Use viewport-hide for level content you want present (physics, scripts, references) but off until gameplay or a behavior sets entity.node.isVisible = true.

Use Collider › Make Invisible when the object should stay visible while authoring in Blender but ship as collision-only (invisible triggers, hidden blocking volumes).

At runtime use SetEntityActive(entity, active) for Unity SetActive — see 06 — Physics › Runtime enable / disable.

Uncheck Shadow under ray visibility on huge ground meshes. They receive shadows from props without expanding the sun shadow frustum. For explicit control (including cast-only or no shadow interaction), add a Mesh Shadows component instead — it overrides ray visibility when present.

The validator <a name="validator"></a>

export/validate.py runs from the Validate button, from Export, and from every Live Link export.

Checks include: missing or empty script files. Duplicate component instance names on one object. Entity references to render-disabled objects. Stale prefab entity pointers (cross-instance / cross-prefab picks that likely need a level override re-pick). MESH collider + DYNAMIC body. MESH-shaped triggers (never fire in Havok). Trigger events on non-trigger colliders or without a target. Mixed trigger/non-trigger colliders on one entity (compound body). Constraints missing a target or physics on either end. Components or animation autoplay on a skinned mesh (belongs on the armature — why). Rendering Group id outside 0–3. Custom Layer Mask negative or above 32-bit range. AREA lights. Duplicate GUIDs. Missing audio file. No active camera. Input Actions (duplicate map/action names, actions with no bindings, @inputMap("Name") referencing a missing map, Scene Default map not found). Collision Layers (duplicate/empty layer names, matrix size mismatch, COLLISION_LAYER referencing unknown layer, component on entity without Collider/Rigid Body).

Debug Build & debug keys

The Export panel Debug Build checkbox writes a top-level "debug" flag into the manifest (missing = true for old manifests). That becomes level.debugEnabled.

It gates runtime debug keys in main.ts. C shows collider wireframes via PhysicsViewer. I opens the Babylon Inspector (lazily imported so it never ships in production bundles). It also gates the debugColliders loader option. Untick for release exports.

Project Control Panel <a name="control-panel"></a>

tools/project-control-panel/ (@bjs/project-control-panel) is a local web hub on port 3200 (npm start, or npx b2bkit-control-panel in an installed project). It starts the current app Vite dev server, runs the packaged bjs-mcp for Cursor, browses per-level JSON asset folders, serves the bundled docs, and publishes web builds. It does not host embedded Babylon editors.

Full reference: Control Panel docs.

Typical loop: pick project + level in the hub → Start All Services → open the runtime preview link → export from Blender via Live Link into game/public/levels/<level>/ (path shown in the hub).

Versioning & artifacts

Engine package.json(s), the Project Control Panel, and blender_addon/blender_manifest.toml move in lockstep (currently engine v1.0.3 · Blender add-on v1.0.3). Release with npm run release -- --version X.Y.Z. That runs scripts/assemble-kit-package.mjs, which rebuilds the documentation site and the MCP doc-embedding index, builds the engine, panel, and bjs-mcp, then bundles the compiled panel, MCP with its search index and prose sources, the fresh docs site, and the add-on zip into b2bkit. npm pack runs the same assembly through a prepack hook. Manifest schema is v5; additive optional fields (such as exporterVersion) do not bump it.
