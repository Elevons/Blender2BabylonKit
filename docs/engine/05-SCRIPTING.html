Entity (core/Entity.ts)

The runtime wrapper around one Blender object. Fields include id (GUID), name, node (the glb TransformNode), tag, attachments, behaviors, optional body (Havok), animations, and sounds.

attachments is the live registry. It holds one row per successfully applied component. Types live in core/attachments.ts.

Component vs behavior: a component is authored data (TAG, COLLIDER, SCRIPT, …). A behavior is a runtime script class from a SCRIPT component.

Query attachments with GetAttachment(type), GetAttachmentsOfType(type), or HasAttachment(type). When one entity has multiple rows of the same type, use the Blender header Name field. Export writes it as optional name on the component row. Resolve at runtime with GetNamedAttachment(type, name) or GetScript(name).

GetBehavior(Ctor) returns only the first instance of that class. Mutation (add or remove rows) is app-code only through level.componentHost. See 14 — API Guide › ComponentHost. Behaviors do not receive Level.

Full apply chain: trace-components · Blender authoring: Blender trace-components.

Three ways to reach another entity: an @exposed({type:"entity"}) field (cleanest), node.metadata.bjsEntity from a node, or level.ById / ByTag.

Behavior lifecycle (scripting/Behavior.ts)

Ten hooks — override only what you need. Names are PascalCase. A lowercase onStart silently never runs. It stops overriding the base hook. Interactive trace with Babylon integration: trace-lifecycle.

HookWhenNotes
OnStart(): voidOnce, after the whole level loads and every @exposed entity ref resolvesCross-entity order is unspecified. Guard null refs. Subscribe observers here. Clean up in OnDestroy.
OnPostReady(): voidOnce, after NME compile and post attach (level.postReady)Use for level.post / Default Rendering Pipeline work (zone LUT swaps). Runs after OnStart at load; spawned/runtime scripts get it right after OnStart when post is already ready.
OnUpdate(deltaSeconds: number): voidEvery render framedeltaSeconds is seconds (Engine.getDeltaTime() / 1000). Scale continuous motion by it. Babylon velocities are already per-second. Do not multiply those by deltaSeconds.
OnDestroy(): voidLevel.DisposeRemove observers and dispose constraints you created. Errors are swallowed during teardown.
OnMessage(message, source): voidEvent Messages, 3D GUI clicks, or SendMessagesource is the sending entity. See trace-trigger for the physics path.
OnCollisionEnter(other, contact)Solid collider first contacts another bodyBoth bodies receive the callback (Unity semantics). Opt-in. Only overridden hooks enable Havok collision callbacks.
OnCollisionStay(other, contact)While solid contact continuesDirect relay of Havok COLLISION_CONTINUED. Stops when bodies sleep (like Unity).
OnCollisionExit(other)Solid contact endsRequires collision-ended callbacks on the body.
OnTriggerEnter(other)Trigger volume first overlappedNo per-body enable flag. The plugin observable fires for trigger shapes.
OnTriggerExit(other)Trigger overlap endsNo OnTriggerStay. Havok has no TRIGGER_CONTINUED. Track overlap state in code if needed.

Injected before OnStart: entity, scene. node is a getter for entity.node. input? is set when the script has no @inputMap fields (scene default map).

How it plugs into Babylon

Hooks are not called during InstantiateScripts. OnStart runs only after Level.Begin at end of load. OnPostReady runs after late rendering (NotifyPostReady).

Each scene.render() (from the app runRenderLoop) fires RunFrame on onBeforeRenderObservable. Order is input process, all OnUpdate, camera updaters, then input end frame.

The registry contract (scripting/BehaviorRegistry.ts)

BehaviorRegistry maps a SCRIPT component script field (filename stem / registry key) to a Behavior class. It does not use the optional Blender Name / manifest name instance label.

main.ts auto-registers every file in behaviors/ by filename stem via import.meta.glob + AutoRegisterBehaviors. That key matches what Blender Open Script… stores.

Contract: one class per file, file named after the class, export default.

@exposed (scripting/exposed.ts)

Marks a field editable per-object in Blender. The decorator only records name and UI hints in a WeakMap. ApplyExposedVars writes manifest stored values onto the instance before OnStart. Entity refs defer to the loader second pass. Lists are handled per element type.

Types: float int bool string file vector2 vector3 color entity enum list (+ of for list elements). file shows a Blender file picker; export copies the asset to post/ via copy_asset (LUTs and other post assets). Blender cannot run TS. core/script_parse.py regex-parses the source. Rules: single-line literal defaults only, explicit type:"entity" hints, entity lists start [], and the decorator name stays lowercase (the cross-language contract). See STYLE_GUIDE. Press Sync in Blender after changing exposed fields.

Coordinate axes

Behavior scripts use Blender local axes on loaded nodes (+Y forward, +Z up). Manifest physics fields are converted to Babylon Y-up at export; @exposed vector3 vars are not. lookAt aligns local +Y; parented nodes need Space.WORLD.
