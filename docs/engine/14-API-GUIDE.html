14 — API Guide (runtime)

Feature inventory: 13 — Feature List · Behavior quick-start: LLM_SCRIPTING_CONTEXT.md · Scripting prose: 05 — Scripting · Input: 12 — Input

This guide is a reference for behavior authors and anyone who reads runtime code. Import from @bjs/engine in app behavior files. This guide covers the kit's public surface. It does not cover every Babylon.js API.

Quick example

import { Behavior, exposed, inputMap, type Entity } from "@bjs/engine";
import type { InputActionMap } from "@bjs/engine";
import { Vector3 } from "@babylonjs/core";

export default class Patrol extends Behavior
{
  @exposed({ min: 0, max: 10 }) speed = 2;
  @exposed({ type: "entity" }) target!: Entity;
  @inputMap("Player") player!: InputActionMap;

  OnStart(): void
  {
    // target is resolved before this runs
  }

  OnUpdate(deltaSeconds: number): void
  {
    const move = this.player.FindAction("Move")?.ReadVector2();
    if (move !== undefined)
    {
      this.node.position.addInPlace(new Vector3(move.x, 0, move.y).scale(this.speed * deltaSeconds));
    }
  }

  OnMessage(message: string, source: Entity): void
  {
    if (message === "Alert")
    {
      // react to trigger or GUI click from source
    }
  }
}

Behavior

This class is the base class for all scripts. Use one export default class per file. The filename stem is the Blender registry key (Patrol.ts → "Patrol").

Lifecycle (PascalCase required)

MethodWhen
OnStart(): voidOnce, after load finishes and all @exposed entity refs resolve
OnPostReady(): voidOnce, after NME compile and post attach (level.postReady)
OnDisable(): voidWhen the entity becomes effectively inactive (SetEntityActive / hierarchy)
OnEnable(): voidWhen the entity becomes effectively active again
OnUpdate(deltaSeconds: number): voidEvery frame, inside Level.RunFrame (before physics step). Skipped when !IsEntityActive(entity)
OnDestroy(): voidWhen the level is disposed
OnMessage(message, source): voidWhen this entity receives a message (Event Messages, 3D GUI, SendMessage)
OnCollisionEnter(other, contact): voidSolid collider first contacts another entity (contact is a CollisionContact: point, normal, impulse, distance)
OnCollisionStay(other, contact): voidWhile solid contact continues (Havok COLLISION_CONTINUED. Stops when bodies sleep)
OnCollisionExit(other): voidSolid contact ends
OnTriggerEnter(other): voidTrigger volume on this entity first overlapped
OnTriggerExit(other): voidTrigger overlap ends (no OnTriggerStay). Track overlap state in code if needed

Physics hooks are optional. Override one hook and the engine enables the matching Havok callbacks. You do not need a manual observable subscription. Both bodies in a solid contact receive collision hooks (Unity semantics). Trigger hooks fire on the trigger entity's behaviors. See 06 — Physics › Collision lifecycle hooks.

Convenience arrays on Entity (sounds, behaviors, …) mirror attachments for common access. At load and at runtime, code writes attachments with RegisterAttachment. Runtime remove goes through ComponentHost (see below).

ComponentHost (runtime mutations)

App code can change components after load through level.componentHost. File: packages/engine/src/core/ComponentHost.ts. Behaviors do not receive Level. Add or remove components from your app layer. You can also pass results into behaviors through messages or @exposed entity refs.

await level.componentHost.AddComponent(enemy, {
  type: "SCRIPT",
  script: "Patrol",
  vars: { speed: 3 },
});

await level.componentHost.RemoveComponent(enemy, "SCRIPT", 0);

Methods

MethodDescription
AddComponent(entity, component, options?)Apply one manifest-shaped component. options.parentEntityId is required for GUI3D controls nested under a panel entity.
RemoveComponent(entity, type, index?)Remove one attachment row (index = which row of that type, default 0). Runs OnDestroy for SCRIPT rows.

Runtime support by type

Supported at runtimeLoad-only (policy error)

Mutations are ephemeral. They are not written back to .scene.json. A SCRIPT added after level.Begin() runs OnStart immediately (and OnPostReady when level.postReady is already true). COLLIDER or RIGIDBODY changes rebuild the entity's single Havok body from all remaining attachment data.

Input (@inputMap + polling)

See 12 — Input for authoring (stick vs 1D/2D composites, control type, gamepad labels, LT/RT as axis 4/5, axisHalf, disambiguation). In behaviors, use:

@inputMap("Player") player!: InputActionMap;  // named map
@inputMap("Vehicle") vehicle!: InputActionMap; // e.g. CarController

// Vector 2 action — Type: Value, Control Type: Vector 2 in Blender
const control = this.vehicle.FindAction("Main Control")?.ReadVector2() ?? { x: 0, y: 0 };
const throttle = control.y;
const steer = control.x;

InputAction (callbacks)

action.started.add(fn), action.performed.add(fn), and action.canceled.add(fn) use the same semantics as Unity Input System.

Global access (optional)

You can use InputManager.actions, InputManager.FindAction("Player/Move"), and InputManager.GetDefaultMap(). Prefer @inputMap fields on behaviors.

BehaviorRegistry

This registry maps script name to class. Apps register before load:

const registry = new BehaviorRegistry();
const modules = import.meta.glob("./behaviors/*.{ts,js}", { eager: true });
AutoRegisterBehaviors(registry, modules);
const level = await new LevelLoader(scene, registry).Load(manifestUrl);

The loader calls registry.Create("Patrol") internally for each SCRIPT row.

App bootstrap (not in behaviors)

A typical main.ts handles these tasks. See 02 — Runtime Basics:

  1. FetchAndValidateManifest(url) — optional; required before CreateLevelEngine when using large-world rendering
  2. CreateLevelEngine(canvas, antialias, manifest)
  3. new Scene(engine)
  4. await EnableHavokPhysics(scene, …) — before Load
  5. LevelLoader.Load(manifestUrl, manifest?, options?)
  6. engine.runRenderLoop(() => scene.render())

Physics (from behaviors)

When an entity has a body, this.entity.body is a Babylon PhysicsBody. Use Havok APIs for impulses, velocities, and similar values. Toggle the collider overlay with the app debug key and level.ShowColliders() (when level.debugEnabled).

Trigger volume queries

Exported from @bjs/engine (subsystems/physics/shapes.ts). Test whether a probe is inside a BOX/SPHERE trigger collider. Manual colliders use manifest dimensions; auto-fit colliders resolve owned-mesh bounds the same way as Havok body build. Analytic math — not Havok overlap events — so bodyless probes work in OnStart/OnUpdate. See 06 — Physics › Trigger volume queries.

FunctionDescription
IsEntityInsideColliderVolume(probe, volume, collider?)probe.node world position inside volume's trigger collider
IsPointInsideColliderVolume(point, volume, collider?)World Vector3 inside volume trigger collider

Zone behaviors poll in OnStart/OnUpdate. Assign an explicit probe entity when the script host is not the sample point. Fragment: poll-trigger-volume.

Messages

Event Messages and 3D GUI buttons call targetEntity.SendMessage(message, sourceEntity). Every behavior on the target receives OnMessage(message, source). Use the same string names you authored in Blender event rows.

Runtime lights (FindLightForNode)

This helper is exported from @bjs/engine (subsystems/lights.ts). It resolves the Babylon Light for a lamp entity's glTF node. It walks the parent chain, then matches by name, then checks lights inside ClusteredLightContainer.

import { FindLightForNode } from "@bjs/engine";

const light = FindLightForNode(this.scene, lampEntity.node);
if (light !== null)
{
  light.intensity = value;
}

Do not iterate scene.lights alone on large scenes. Clustered point and spot lamps are removed from that array. You can still drive them through this helper. See increaselights.ts and 07-RENDERING.html (punctual light budget). Set budget and per-lamp clustering in Blender (Scene › Export, Object › Light › Cluster When Over Budget).

Runtime cameras (FindCameraForNode / CopyLens)

These helpers are exported from @bjs/engine (subsystems/cameras/). FindCameraForNode resolves the Babylon Camera for a camera entity's glTF node. It walks the parent chain, then matches by name. The loader uses the same helper. CopyLens copies FOV, fovMode, clip planes, and projection mode. BuildTypedCamera calls it when Blender Camera-component overrides swap the FreeCamera for Arc/Follow/etc.

import { CopyLens, FindCameraForNode } from "@bjs/engine";
import { ArcRotateCamera } from "@babylonjs/core";

const authored = FindCameraForNode(this.scene, this.node);
const camera = new ArcRotateCamera(/* … */);
if (authored !== null)
{
  CopyLens(authored, camera);
}
this.scene.activeCamera = camera;

Prefer to author camera type in Blender. Use these helpers when a behavior must create its own camera (see TrainCamera.ts). Without CopyLens, a script-built camera keeps Babylon defaults. It will silently ignore the authored FOV.

AnimatorController

This controller is a built-in FSM from an ANIMATOR component (not a SCRIPT). It is exported from @bjs/engine (subsystems/animatorController.ts). Retrieve it with entity.GetAttachment("ANIMATOR")?.behavior.

Related exports

@bjs/engine also re-exports manifest types (core/types/, barrel core/types.ts), subsystem helpers (physics, lights, cameras, …), and UI loaders. App code and advanced scripts use these most often. Behavior authors usually need Behavior, exposed, inputMap, and Babylon types only.
