Create a game with the published kit

Canonical starter for a project that depends on the published Babylon Level Kit. One package (b2bkit) carries the runtime, the Project Control Panel, a prebuilt bjs-mcp behavior-authoring server, the documentation site, and the matching Blender add-on zip. Kit version: __KIT_VERSION__.

1. Prerequisites

  • Node.js 18+
  • Blender 4.2 or newer (see the add-on manifest minimum)
  • A browser that can run Babylon.js / WebGL

2. Create the project layout

Use one install of the kit package. Scaffolding sits at the project root; the playable app is a self-contained game/ folder (same shape as this monorepo's game/ example).

my-project/
  package.json              # workspaces: ["game"] (optional thin root)
  game/
    package.json            # depends on b2bkit, @babylonjs/*, vite
    vite.config.ts          # Live Link reload of public/levels/
    index.html
    b2bkit-project.json     # entryLevel, blenderExportPath, dev.port
    src/main.ts
    src/behaviors/
    workspace/              # in-progress GUI / particles / materials
    public/levels/          # Blender exports
    Blender/                # your .blend files

npm install pulls the kit (runtime, panel CLI, prebuilt MCP server, docs site, add-on zip) and Babylon peers. The kit exposes three commands: b2bkit-control-panel, b2bkit-addon-path, and b2bkit-mcp.

3. Install the Blender add-on

  1. From the project root: npx b2bkit-addon-path — prints the zip path inside node_modules
  2. Blender → Edit → Preferences → Get Extensions → Install from Disk…
  3. Enable the extension; confirm the version matches the kit package

4. Open the Project Control Panel

From the project root (the folder that contains game/):

npx b2bkit-control-panel

Use Start All / Vite to run the game, jump levels, edit workspace assets, and publish. The panel serves the bundled documentation at /docs/, and its Services panel starts bjs-mcp against this project.

5. Author and export

  1. Set Blender Export Level to game/public/levels/<LevelName>/<LevelName>.glb
  2. Enable Live Link after the first export
  3. The Vite plugin reloads when files under public/levels/ change

6. Wire the app

game/src/main.ts creates the engine, registers behaviors with AutoRegisterBehaviors over ./behaviors/*, and loads a .scene.json. Behavior filenames must match the Blender SCRIPT registry keys.

To author behaviors with Cursor, start bjs-mcp from the Services panel (or run npx b2bkit-mcp) and copy the Cursor config from the panel into ~/.cursor/mcp.json. The server reads this project's game/src/behaviors/, levels, and Input Actions, and answers documentation queries from the packaged docs — no separate clone or build.

7. Assets

  • In progress: game/workspace/{gui,particles,materials,…}/
  • Ship with a level: copy into game/public/levels/<Level>/ (manifest paths are URL-fetched, not JS imports)
  • Never put those JSONs under src/

8. Run and publish

The control panel starts the game Vite loop. Publish copies included public/levels/ into dist/. Optional encryption packs them into assets.pak. Published builds use portable ./levels/… URLs (Vite base: './'); the service worker still serves encrypted level paths. See 02 — Publishing for path matching, first-load reload, and 404 checks.

9. Version compatibility

Runtime, control panel, and Blender add-on ship as one kit version. Exported scenes stamp exporterVersion beside the schema version. If the schema does not match, the engine reports which add-on wrote the scene and asks you to update the kit or re-export.
