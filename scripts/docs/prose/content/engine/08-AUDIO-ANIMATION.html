08 — Audio & Animation

Audio (subsystems/audio.ts)

AUDIO components become audio engine v2 StaticSound instances. The legacy Sound class is deprecated. Component fields include file, volume, loop, autoPlay, spatial settings, maxDistance, and playbackRate.

The runtime creates one audio engine on first use (CreateAudioEngineAsync). It loads each sound with CreateSoundAsync. Set spatialEnabled at creation time. This avoids latency on first spatial playback. Call sound.spatial.attach(entity.node) so 3D sounds follow the entity.

Each sound name is the file stem. For example, audio/door.mp3 becomes "door". Get sounds with entity.GetSound or entity.GetAttachment("AUDIO")?.sound.

Browsers block autoplay until the user interacts with the page. Auto-play sounds call audioEngine.unlockAsync(). That promise resolves on the first user gesture. Level load does not wait for unlock. The loader collects sound creation promises during the entity pass. FinalizeLevel settles those promises. A bad audio file logs an error. It does not fail the whole level.

The exporter copies sound files into audio/ next to the manifest. The level dispose step removes sounds.

Animation (subsystems/animation.ts)

Export uses Blender ACTIONS mode. Stashed and active Actions become glTF animations. The loader builds global AnimationGroup instances from those clips.

Clip names match the Action name by default. They do not match the NLA strip display name. Rename an NLA track away from NlaTrack* or [Action Stash]* to override the clip name. Tracks that share the same override merge into one name.

Stashed Actions on muted tracks still export. The exporter skips muted strips and multi-strip tracks. These rules match glTF-Blender-IO. Use one Action per NLA track when you can.

FindAnimationGroups scopes groups to an entity by membership. A group belongs to a node when any animation in the group targets that node or a descendant. The loader does not rely on globally unique clip names.

ApplyAutoPlayAnimations first stops auto-started groups from the glTF loader. It then plays each entity clip. Match order is exact name, then contains, then first clip. Loop and speed come from the entity settings.

At runtime, use entity.animations and entity.GetAnimation("Walk")?.start(true). See the ClipSwitcher behavior for clip cycling.

For continuous loops, trim end holds in the Action. Make the last pose match the first pose. A short dead zone on a short swim clip looks like a pause every cycle.

Animator component (subsystems/animatorController.ts)

Add an ANIMATOR component on the armature for multi-state locomotion. Edit Animator opens that object's BJSAnimationStateTree in the Node Editor.

The graph uses these node types. Entry is the default state. State holds an Action clip plus loop and speed. Parameter is a float, bool, int, or trigger. Transition lists AND conditions between states.

Each armature needs its own graph. State clip dropdowns list Actions on the object that owns the open tree. They do not keep a sticky selection from a previous object.

Parameter defaults sync into the component Parameters panel. Press Sync after graph edits. Add nodes from the Node Editor Add menu or the BJS sidebar tab.

Export walks the graph into the manifest. The loader builds a built-in AnimatorController. It extends Behavior and is not a SCRIPT component.

Drive the controller from other behaviors with entity.GetAttachment("ANIMATOR")?.behavior. Call SetFloat, SetBool, SetInt, or SetTrigger. Conditions can also read Input Actions or OnMessage without extra script glue.

Do not enable Animation-panel autoplay on the same object. The Animator owns playback. Transitions are instant in v1. Crossfade is not supported yet.

The skinned-mesh rule (important)

For rigged characters, put everything on the armature object. That includes GUID, Animation settings, Animator, and Script components.

Two glTF facts make the mesh object a trap. First, a skinned mesh node transform is ignored. Joints define the final pose. A script that moves the mesh entity moves nothing visible.

Second, skeletal clips target joint nodes under the armature. Clip scoping on the mesh entity finds zero clips. Both failures are silent.

The validator warns when components or autoplay sit on a skinned mesh.
