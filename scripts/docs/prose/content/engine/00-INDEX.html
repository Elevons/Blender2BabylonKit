Babylon Level Kit — Engine (Runtime) Documentation

The runtime half of the kit, current as of __KIT_VERSION__. The interactive version is the HTML subsystem diagram set in this folder — open index.html and use the bottom nav (a subsystem-diagram row + a Traces row for code walk-throughs; "Blender docs →" jumps to the editor side).

Looking for something specific? Open the searchable landing page at index.html and type a term (e.g. collision, export, input) to surface the relevant pages from both the engine and Blender sides.

Doc types (quick glossary)

  • Subsystem diagram — clickable node graph for one slice of the engine (e.g. physics.html). Not Blender AREA lights. Click a node to see its description; related Trace links in the side panel are added at build time from PAGE_TOPICS (see BUILDING-DOCS).
  • Code trace — step-by-step walkthrough with live source extracted at build time (trace-*.html). The bottom nav highlights the subsystem diagram(s) for the same topic; each step lists matching Diagram links.
  • Prose chapter — longer narrative pages like this one (01-ARCHITECTURE.html, …).

What the runtime does

@bjs/engine (packages/engine/) loads the two artifacts Blender exports — level.glb (everything glTF can express) and level.scene.json (everything it can't) — and turns them into a live Level. LevelLoader.Load appends the glb, indexes nodes by GUID, builds an Entity per manifest entry, applies components through small subsystems (physics, lights, cameras, audio, …), then runs your Behavior scripts. See Architecture for the two-artifact split and Blender Add-on for the editor side.

Regenerating

npm run docs:build regenerates both sides from the shared shell template (docs/_template/diagram-shell.html) and rebuilds the searchable landing page. npm run docs:trace rebuilds only this folder; it re-extracts every trace's source from packages/engine/. A renamed/deleted symbol fails the build loudly — the anti-rot guard. (The Blender side alone is npm run docs:blender.)
