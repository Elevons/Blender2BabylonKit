Subsystem diagram: rendering.html · Code traces: Lights · Cameras · Shadows · Post-processing · Atmosphere · Node materials · Blender: NME authoring

Lights (subsystems/lights.ts)

Lights are automatic. You do not add a component. The glb creates and places the light. ApplyBlenderLight copies the lamp's properties onto it. Blender inserts an orientation-correction node when exporting +Y-up. The GUID node is an *ancestor* of the light.

FindLightForNode walks the whole parent chain. It also searches lights inside a ClusteredLightContainer when punctual clustering ran. POINT maps to Point. SUN maps to Directional. SPOT maps to Spot. AREA is unsupported by glTF. The validator warns for AREA.

Color and intensity copy 1:1 from the manifest (energy → light.intensity). Point and spot power use watts. Sun strength uses W/m². When Atmosphere is on, PBR Sun Intensity (default) may override the sun to π. See Atmosphere below.

SUN lamps export sunAngle (angular diameter, radians). When the lamp casts shadows, SetupShadows maps it to PCSS penumbra. Blender Angle 0° maps to 0. 45° maps to 1. Values above 45° are clamped. Spot lamps export spotSize / spotBlend. There is no fallback light. A dark scene means you must add a lamp in Blender.

Runtime scripts: behaviors that drive lamp intensity (e.g. increaselights) must resolve lights with FindLightForNode(scene, entity.node) from b2bkit. Do not use raw scene.lights. After clustering, punctual lamps are removed from scene.lights. They remain the same Light instances. light.intensity still updates the cluster each frame.

Punctual light budget (subsystems/clusteredLights.ts)

Large light rigs can exceed WebGL's per-shader uniform buffer block limit. The limit is often 12–16 blocks. Babylon uses one block per forward light plus scene, material, and mesh data. The symptom is Unable to compile effect / _finalizePipelineContext in the browser console with a high LIGHTCOUNT define. This is not a Blender export bug.

The loader handles this automatically during FinalizeLevel, before SetupShadows and the first material compile. Authors do not toggle anything in Blender for normal use.

When it kicks in

After the entity pass, count enabled lights in scene.lights. When the count exceeds the budget (default 8), the loader tries to move eligible point and spot lights into a Babylon ClusteredLightContainer. Only lamps with entities[].light.cluster !== false are clustered. The default is all point and spot. Directional (sun) lights stay forward. Shadow maps and PCSS penumbra keep working.

Three outcomes (level.punctualLightingMode)

ModeWhenWhat happened
forwardEnabled lights ≤ budgetNo change. Standard forward PBR per light.
clusteredOver budget and clustering succeededPunctual lights live in one cluster. The cluster counts as a single shader light. The handle is on level.clusteredLights.
forward-expandedOver budget but clustering unavailableengine.disableUniformBuffers = true. The forward path supports more lights. It is slightly slower. It preserves glTF falloff.

On load, check the console for a summary line:

[bjs] punctual lighting: clustered 19 point/spot lights (2 regular scene lights remain; budget 8)

or forward-expanded (uniform buffers disabled; …). You can also read level.punctualLightingMode from gameplay code after LevelLoader.Load.

Clustering details and limits

  • glTF punctual lights export with Light.FALLOFF_GLTF. Clustered lighting only accepts FALLOFF_DEFAULT. The loader converts falloff before addLight. The cluster writes inverse-square attenuation into its light-data texture. This is close to glTF. It is not bit-identical to forward.
  • Clustered lights cannot cast shadows in Babylon. Keep shadow-casting on suns and any punctual lights that must shadow. Expect those to count toward the budget.
  • After clustering, punctual lights are not in scene.lights. Use FindLightForNode or level.clusteredLights.lights from app code to resolve them for runtime intensity changes.
  • IES profiles and projection textures on spots are not clusterable.
  • Devices without WebGL2 float blending fall back to forward-expanded.

Authoring in Blender

Babylon Scene › Export (before the Export Level button):

  • Light Budget — max forward scene lights before clustering / UBO fallback (default 8). Exported as scene.lightBudget.
  • Cluster Punctual Lights — when off, never cluster. Use forward-expanded when over budget. Exported as scene.clusterPunctualLights.

Babylon Object › Light (point/spot only): Cluster When Over Budget — uncheck to keep a lamp in the forward shader when the scene exceeds the budget (entities[].light.cluster: false). Use for shadow-casting punctual lamps or hero lights that must not share the cluster path.

Cameras (subsystems/cameras/)

Cameras mirror the lights design. The glb creates a faithful FreeCamera. FindCameraForNode walks parents the same way. ApplyBlenderCamera copies clip range and FOV or ortho mode. The exporter flags the scene's active camera. That sets scene.activeCamera and level.activeCamera. Playback is faithful by default. No controls attach. main.ts adds a fallback ArcRotate only when no camera shipped.

Runtime scripts: when a behavior must create its own camera (instead of a Blender Camera component), resolve the exported camera with FindCameraForNode(scene, entity.node). Copy FOV, clip planes, and projection with CopyLens(source, destination). Both are exported from b2bkit. Typed Camera-component overrides already call CopyLens internally. See TrainCamera.ts.

An opt-in CAMERA component overrides the type via BuildTypedCamera. It derives the new camera from the faithful one's world transform. It starts exactly where Blender framed it. It copies the lens, then disposes the original.

Per-type builders: UNIVERSAL (free-fly + key scheme). ARC (orbit. Optional target re-pivots in the second pass. setPosition(eye) keeps the Blender framing. Optional Track Target drives the orbit pivot each frame via Level.AddUpdater). FOLLOW-ORBIT (Babylon FollowCamera. useBlenderTransform derives radius, height, and rotationOffset via DeriveFollowFromPosition). FOLLOW-OFFSET (a UniversalCamera driven each frame by a Level.AddUpdater to hold the exported world offset).

GEOSPATIAL uses Babylon GeospatialCamera for map-like globe navigation — pan, zoom-to-cursor, tilt. The planet mesh must sit at world origin. Planet Radius must match its radius in scene units. DeriveGeospatialPose raycasts the exported eye and forward against that sphere. It seeds center, yaw, pitch, and radius. Optional min and max zoom and collision checking apply.

Orbit Speed, Zoom Speed, and Pan Speed (manifest orbitSpeed / zoomSpeed / panSpeed, default 1.0) apply to ARC and GEOSPATIAL when controls attach. They are implemented in speeds.ts. ApplyArcRotateControlSpeeds maps to Babylon sensibility and wheel precision. ApplyGeospatialControlSpeeds scales movement.rotationXSpeed, rotationYSpeed, panSpeed, and zoomSpeed.

Free-fly cameras (FREE and UNIVERSAL) also honor an optional Keep Upright toggle (lockRoll). LockCameraRoll bakes the world pose and detaches the glb camera from its orientation-correction parent. Yaw and pitch happen in world space. It pins look-at to world up. It drops any residual view-axis roll each frame. The camera stays level with the horizon.

Targets resolve with entity references in the loader's second pass (pipeline step 5). GEOSPATIAL has no deferred target. Controls (pointer, wheel, keyboard) attach when Attach Controls is on.

Large world rendering / floating origin

When coordinates are very large (geospatial globes, flight sims, open worlds), enable Large World Rendering in Blender's Babylon Scene › Rendering panel. Export writes scene.largeWorldRendering and optional scene.floatingOriginWorldRadius (Havok multi-region radius, default 100000).

The app must fetch the manifest before creating the Babylon engine. CreateLevelEngine sets useLargeWorldRendering. ResolveHavokPhysicsOptions passes the region radius to EnableHavokPhysics. See core/bootstrap.ts and game/src/main.ts. Meshes, behaviors, and the loader otherwise stay unchanged. Babylon offsets shader uniforms relative to the active camera. Havok simulates bodies in regional floating-origin worlds automatically.

Shadows (subsystems/shadows/)

Shadows are driven by each lamp's Cast Shadows toggle. There is one ShadowGenerator per casting light. By default, meshes receive shadows and cast unless Ray Visibility › Shadow is off. When off, export stamps bjs_cast_shadows: 0 in glTF extras and SetupShadows skips that mesh as a caster (receive-only). Typical use: a huge sea floor that should catch train shadows but must not blow up the sun frustum.

Mesh Shadows component (Babylon Object › Rendering) overrides ray visibility and all other shadow settings when enabled. Modes: Cast & Receive, Receive Only, Cast Only, None. Uses the same Apply to Owned Meshes / Apply to Child Entities propagation as Rendering Group and Layer Mask. Applied in ApplyMeshShadows immediately after SetupShadows (subsystems/shadows/meshShadows.ts). Prefab spawns run the same pass in FinalizeSpawn.

Per-light settings: filter (PCF / PCSS / Poisson / Blur ESM / hard), bias, normalBias, darkness, mapSize, frustum minZ/maxZ (set on the *light*. 0 = auto), frustumEdgeFalloff (directional/spot edge fade), and forceBackFaces (render only back faces into the shadow map — strong acne fix, opt-in because it can leak on thin/open meshes). SUN lamps with sunAngle enable PCSS. They set contactHardeningLightSizeUVRatio linearly from the Blender Angle slider (0°→0, 45°→1. Values above 45° are clamped). Loader options: { shadows?, shadowMapSize?, freezeShadows?, cleanBoneMatrixWeights? }. Exposed as level.shadowGenerators.

Static-world freeze. The scene's Freeze Shadows flag (or the freezeShadows loader option) renders each shadow map once then freezes it (REFRESHRATE_RENDER_ONCE). This is a big perf win. It lets you raise the map resolution. It is valid only when no caster moves. After moving a caster at runtime, call level.RefreshShadows() for a one-shot re-render. cleanBoneMatrixWeights scrubs bad skeleton weights on load. It fixes garbled shadows on skinned meshes.

Acne defaults. Blender lamps export normalBias = 0. That leaves suns striped and point/spot edges speckled. The loader applies a normal-bias floor when a light does not set its own (0.02 directional, 0.03 point/spot). It also tightens the shadow depth range automatically. A stretched depth buffer is the usual cause of acne. Directional suns get autoCalcShadowZBounds (Babylon re-fits minZ/maxZ to the casters each frame) when clip planes are left at auto. Point and spot lights cap shadowMaxZ to the lamp's range. Set a Custom Range in Blender for this to kick in. Explicit clip start/end or normal bias always win over these defaults.

Scene look (environment.ts, fog.ts, atmosphere.ts, postprocess/)

The manifest's scene block drives clear/ambient color, environment texture → IBL, fog (LINEAR/EXP/EXP2), physically based atmosphere, and post-processing. await ApplySceneSettings applies them during FinalizeLevel. Environment loads asynchronously. The skybox is created only after the env texture is ready. ApplyAtmosphere runs immediately after scene settings when the manifest includes an atmosphere block. Post-processing is applied after level.Begin() (so runtime cameras from OnStart receive the stack), then level.NotifyPostReady() runs every behavior's OnPostReady. Zone LUT swaps belong in OnPostReady, not OnStart.

Environment / IBL (subsystems/environment.ts)

Image-based lighting comes from scene.environmentTexture. Without an environment block in the manifest, PBR materials get no cubemap. They only get direct lamps and the optional ambientColor fill. Imported glTF PBR picks up scene IBL automatically. Node Material Editor shaders need a ReflectionBlock wired to the PBRMetallicRoughness block's reflection input. Leave the Reflection block's texture empty to use scene.environmentTexture. Do not wire a ReflectionTextureBlock into the Reflection block's color input unless you intend to tint. Assign it a texture, or IBL is multiplied to black.

Atmosphere (subsystems/atmosphere.ts)

The Babylon Atmosphere addon (@babylonjs/addons/atmosphere) provides a physically based sky and aerial perspective. It automatically integrates with PBRMaterial for consistent lighting. It requires WebGL 2 or WebGPU. The runtime calls Atmosphere.IsSupported(engine) and logs a warning if unsupported.

Reflection probes (subsystems/reflectionProbes.ts)

There are two reflection sources in a level:

  • Scene IBL (scene.environmentTexture) — the sky / environment from Babylon Scene › Environment. Used by PBR materials everywhere by default.
  • Reflection probes — local cubemaps baked from nearby meshes around a probe empty. Used only inside an authored influence volume.

A Reflection Probe component creates a Babylon ReflectionProbe. It renders an authored render list into six cubemap faces. Then AssignProbeMaterials sets material.reflectionTexture = probe.cubeTexture on level meshes whose bounds center falls inside the volume. Outside the volume, materials keep scene IBL.

Skybox and IBL

The visible skybox (hdrSkyBox, BackgroundSkybox, …) is a runtime mesh. AssignProbeMaterials never overrides it (IsSkyboxMesh in environment.ts). The background sky always keeps scene IBL even when the camera is inside a probe volume.

Probes do not capture the IBL sky into their cubemap. They only capture meshes in the render list. Glossy level surfaces inside the influence volume (water, metal, etc.) will reflect that local bake, not the HDR sky. For sky-dominated reflections, rely on Environment / IBL. Keep the influence volume tight around objects that need local geometry reflections.

Limitations (v1). NME materials that wire reflections only through a ReflectionBlock (not reflectionTexture) are not auto-bound. Probes are static at load position. There is no probe blending. One probe per mesh. Skybox meshes cannot be added to the render list from Blender (they are not exported entities).

Node materials (subsystems/materials/)

Standard glTF PBR from Blender rides in the .glb. For custom shaders authored in the Node Material Editor, open Properties › Material. Select the material in the slot list. Use the Babylon panel (per material datablock, not per object). Export copies the JSON to materials/ and writes a top-level manifest block:

"materials": [
  {
    "name": "Water",
    "file": "materials/water.json",
    "textures": [
      { "blockId": 42, "blockName": "albedo", "file": "materials/albedo.png" }
    ],
    "inputs": [
      { "blockId": 21, "blockName": "fillColor", "type": "COLOR4", "value": [0.15, 0.4, 1, 0.35] }
    ],
    "gradients": [
      {
        "blockId": 22553,
        "blockName": "Gradient",
        "colorSteps": [
          { "step": 0, "color": { "r": 0, "g": 0, "b": 0 } },
          { "step": 1, "color": { "r": 1, "g": 1, "b": 1 } }
        ]
      }
    ]
  }
]

Matching. Runtime replaces mesh.material when mesh.material.name equals the manifest name (Blender / glTF material name). Parsed node materials are cached per manifest entry (file + name). Several Blender materials can share one NME JSON yet keep distinct texture, input, and gradient overrides.

Scan NME. Click Scan NME in the Babylon material panel after picking a JSON. It lists ImageSourceBlock / TextureBlock slots. It lists inspector-visible InputBlock parameters (visibleInInspector: true in NME — not system values like World or View). It lists inspector-visible GradientBlock nodes (mark the gradient block Visible in Inspector in NME). Tune floats, colors, vectors, and booleans in Parameters. Edit gradient color stops (step 0–1 + RGB) in Gradients. Export copies picked images into materials/. It patches texture url / name, input value, and gradient colorSteps in the exported JSON. It strips embedded base64String / internalTextureLabel when overriding a texture slot. When several Blender materials share the same NME source file, export copies that JSON once. Later materials patch the same exported copy in place. Particle systems use the same texture pattern on the Particles component (Scan Textures lists ParticleTextureSourceBlock slots only).

Embedded textures. NME can store image bytes inside the JSON (texture.url as a data:…;base64,… URI, or a base64String field). The runtime loads these directly from the JSON. No external file is required. Embedded slots are skipped by export override logic. Export does not try to replace them with empty paths. For smaller manifests and easier iteration, use Extract Textures… (bjs.extract_nme_textures). Pick a folder. The add-on writes {BlockName}_{blockId}.png (or .jpg) beside the JSON. It rewrites each block's url to the relative filename. Then it runs Scan NME and fills the matching texture rows. After that, assign or re-export like any external texture. NME saves that put the data URI only in texture.name with an empty url do not load. Re-save from NME or run Extract Textures… so bytes live on texture.url.

Runtime load (two stages). Early in Load, ApplyNodeMaterials parses each NME JSON (parseSerializedObject + urlRewriter for relative URLs beside the JSON). It applies manifest textures[] via BindManifestTextures (authoring wins over embedded JSON). It applies manifest inputs[] via BindManifestInputs. It applies manifest gradients[] via BindManifestGradients. Then it assigns the result to matching meshes. Block ids from the manifest resolve through the material's editorData.map (NME JSON id → runtime uniqueId). blockName is a fallback. Parsed materials are cached per manifest entry (file + name). No build() yet — shader compile is deferred so ReflectionBlock can see scene.environmentTexture and gradient colorSteps are baked at compile time.

Single compile. In FinalizeLevel, after await ApplySceneSettings (environment IBL when declared) and atmosphere setup, BuildNodeMaterials walks every scene NodeMaterial. It awaits whenTexturesReadyAsync(). Then it calls build() once per unique material. Levels without NME materials or without an environment block still take this path when node materials exist. Compile simply runs without scene IBL when no env texture was loaded.

Workflow. Save from NME into the level's materials/ folder (mark shader uniforms and gradient blocks Visible in Inspector when you want them in Blender. Add a Reflection block for IBL) → Material Properties → Babylon panel → pick JSON → optional Extract Textures… when the JSON still embeds images → Scan NME → tune Parameters, Gradients, and assign any external texture images → export. Trace: trace-materials.html · Blender: trace-materials.

Detail maps (subsystems/materials/detailMapApply.ts)

Standard glTF PBR from Blender stays in the .glb. To tile a secondary detail texture over that material at runtime (Babylon DetailMapConfiguration), use the Detail Map box in the same Properties › Material › Babylon panel. It is independent of NME overrides.

Assign a pre-packed detail map or separate Albedo / Normal / Roughness images. Packed is optional when separate channels are set. Export packs separate channels into one PNG using Blender's image API. Babylon Unity channel layout: R = greyscale albedo, G = normal green, B = roughness, A = normal red. Missing channels → 0.5 gray to disable that effect.

Tune UV Set (0 = first UV / UVMap → glTF TEXCOORD_0, 1 = second UV → TEXCOORD_1, …). Export writes it as coordinatesIndex. Also tune UV Scale (tile count on that layer), Diffuse Blend, Roughness Blend (PBR only), Bump Level, and Normal Blend (Whiteout / RNM).

Formats. PNG, JPG, or WEBP only. The runtime loads these in the browser. TIFF/EXR and other formats are rejected. Validate warns before export. Export warns if an enabled detail map could not be written. Validate also warns when the chosen UV set exceeds a mesh's UV layer count.

Live Link re-exports packed detail PNGs and the manifest detailMaps[] block on every save.

"detailMaps": [
  {
    "name": "Marble",
    "file": "materials/Marble_detail.png",

    "uvScale": 10,

Matching. After the glb loads (and after any NME replacement), ApplyDetailMaps matches scene.materials[].name to manifest name. It configures material.detailMap (texture, coordinatesIndex, blend levels, UV scale). Node Materials are skipped. If both NME and detail map are authored on one material, NME wins.

Post-processing (subsystems/postprocess/)

Handles land on level.post (PostProcessingHandles: pipeline?, ssao?). Use RetargetPostProcessing(handles, camera) if gameplay swaps the active camera later (default pipeline only today).

Color grading LUT formats. Babylon's built-in ColorGradingTexture parses .3dl only. Adobe/IRIDAS .cube files (Premiere, DaVinci, free LUT packs) load through CubeColorGradingTexture in subsystems/postprocess/cubeLutTexture.ts into the same Default Rendering Pipeline image-processing pass (colorGradingBGR=false for standard RGB). Strip .png LUTs load as 2D textures. Format reference: babylon-cube-luts (Heaust-ops, MIT). 1D .cube LUTs are not supported. Export copies the authored file to post/ via copy_asset. Runtime helper: ApplyColorGradingLut (exported from subsystems/postprocess/) — use on level.post.pipeline.imageProcessing for zone swaps in OnPostReady; do not load .cube as a plain Texture. Example: FogChanger.ts polls IsEntityInsideColliderVolume each frame (ACES outside, @exposed({ type: "file" }) LUT inside).

When scene.postProcessing.defaultPipeline is true, the runtime builds Babylon's DefaultRenderingPipeline (HDR on). Supported effects:

Blender UI

Babylon Scene › Environment (ui/scene_panels.py, BJS_PT_scene_environment). Default Environment (IBL without a World texture). Intensity and Rotation Y when default env is active (hidden when a World texture wins). Show Skybox (IBL-only background when off). Skybox Ignores Fog (disabled when Show Skybox is off). The panel previews the texture on the active World Output chain via scene/environment.py.

Babylon Scene › Atmosphere (ui/scene_panels.py). Physically based sky settings on scene.bjs_scene.atmosphere (scene/atmosphere.py). Export serialization is in export/atmosphere.py.

Babylon Scene › Post-Processing (ui/post_panels.py). Settings live on scene.bjs_scene.post (scene/post_processing.py). Export serialization is in export/post_processing.py (LUT files — .3dl, .cube, or strip .png — copied via copy_asset → post/). Exposure and contrast export as 1.0 when tone mapping is off. Stale panel values do not crush the image.
