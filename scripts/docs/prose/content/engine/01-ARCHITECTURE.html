The core idea: two artifacts

If glTF can already express it, the glb owns it. The engine writes no code for it. If glTF cannot express it, the data goes in the manifest. A small subsystem applies it.

To learn how the loaded Level hooks into Babylon's render loop (runRenderLoop, OnUpdate, delta time), read 02 — Runtime Basics next.

ArtifactCarriesConsumed by
level.glbgeometry, transforms, hierarchy, materials (standard PBR), lights, cameras, animation clipsBabylon's glTF importer
level.scene.jsoncomponents (TAG/RENDERING_GROUP/LAYER_MASK/COLLISION_LAYER/COLLIDER/RIGIDBODY/SCRIPT/CAMERA/AUDIO/CONSTRAINT/…), optional materials[] (Node Material Editor overrides), per-light/camera/scene settings, scene.inputActions + scene.defaultInputMap, scene.collisionLayers, schema v4our LevelLoader

The manifest never duplicates the glb. It only adds data. This is why there is a subsystems/physics/ but no meshes.ts. Meshes ride entirely in the glb.

Entity identity (GUIDs)

Every addressable Blender object gets a GUID in a custom property (bjs_id, defined once as ID_KEY on both sides). The exporter writes it into the glTF node's extras. The manifest references the same GUID. At load it surfaces at node.metadata.gltf.extras.bjs_id (via the ExtrasAsMetadata loader extension). The loader matches manifest entity to glb node by GUID. Name serves as a legacy fallback.

A GUID is what makes an object an entity. Pure geometry without one just lives in the glb. GUIDs are auto-assigned to anything that needs to be findable. This includes objects with components, lights, and cameras. It also includes any object referenced by an entity field, trigger event, or constraint target.

The GUID is also the discriminator for two subtle cases. Multi-material submeshes have no GUID (so they are "owned" by their wrapper — see Physics). Real parented children do have a GUID (so they are excluded from a parent's collider).

Visibility and shadows (export → load)

Optional detail — skip on first read unless you are debugging invisible objects or shadow casters.

  • Viewport hidden (Blender eye icon, still render-enabled) — transient bjs_visible: false (VISIBLE_KEY) in glTF extras. ApplyNodeVisibility sets node.isVisible = false and disables child lights and cameras.
  • Collider › Make Invisible — makeInvisible: true on the COLLIDER row. The loader's physics handler calls HideEntityNode. Collision-only props can stay visible in Blender while shipping invisible; physics and behaviors still run until SetEntityActive.
  • Runtime SetActive — SetEntityActive(entity, active) sets local activeSelf, reconciles hierarchy (IsEntityActive), fires OnEnable/OnDisable, suspends/resumes Havok and attachments.
  • Shadow ray off (visible_shadow = False) — bjs_cast_shadows: 0 (CAST_SHADOWS_KEY). Meshes stay visible and receive shadows. SetupShadows omits them from casters.
  • Render disabled (hide_render, camera icon) — omitted from glb and manifest (use_renderable=True on the glTF exporter matches the manifest filter).

Monorepo layout

bjs-level-kit/
  package.json            # npm workspaces root: dev / typecheck / release
  packages/engine/        # "b2bkit" — the runtime and the publishable kit
    src/                  #   TypeScript sources (dev imports this across the workspace)
      index.ts            #     public barrel (the game imports "b2bkit")
      core/               #     types.ts (schema) · attachments.ts · ComponentHost.ts · Entity.ts · Level.ts · LevelLoader.ts
                          #     loader/ (manifest · nodeResolution · entityBuilder · componentRegistry · scripts · sceneSettings)
      scripting/          #     Behavior.ts · exposed.ts · BehaviorRegistry.ts
      input/              #     InputManager · maps/actions/bindings · @inputMap
      subsystems/         #     physics lights cameras/ shadows constraints audio
                          #     triggers environment fog atmosphere postprocess animation
                          #     materials (NME overrides)
    dist/                 #   compiled output the published package points at
  game/                   # the single playable example app (Vite + b2bkit-project.json)
  tools/project-control-panel/  # Project Control Panel hub (@bjs/project-control-panel)
  tools/bjs-mcp/          # bjs-mcp behavior-authoring server (@bjs/mcp)
  blender_addon/          # the editor half (Python, Blender 4.2+ extension)
  scripts/                # release + docs build (assemble-kit-package.mjs, build-docs.mjs, …)
  docs/                   # built HTML docs (version-controlled, shipped in the package)

game/ declares "b2bkit": "*". npm install at the root satisfies it with a symlink to packages/engine, and the game's Vite config aliases b2bkit to src/index.ts so engine edits hot-reload with no build step. The published package is different: exports point at dist/, and npm pack assembles the compiled engine, the control panel, a prebuilt bjs-mcp with its search index, the docs site, and the Blender add-on zip into one artifact. Engine, panel, MCP, and Blender add-on versions move in lockstep.
