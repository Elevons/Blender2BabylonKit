02 — Publish

This chapter covers how a kit app boots a level, how you choose which levels ship, and how you build web, desktop, and Android artifacts.

See also: Launcher · Workflow

Overview

Publishing is per project. Shared scripts live in scripts/publish/. Project settings live in babylon-project.json under levels and publish. Artifacts land in the configured output folder (default release/).

The hub Publish panel shells out to the same scripts. CLI works without the hub.

Boot manifest

Apps do not hardcode a level path in main.ts. The Vite plugin ServeBootManifest in the app's vite.config.ts:

  • Serves GET /bjs-boot.json in development (reads babylon-project.json each time)
  • Emits bjs-boot.json into dist/ on build
  • Reloads the browser when babylon-project.json changes

Payload shape:

{
  "startLevel": "Train Scene",
  "manifestPath": "levels/Train Scene/Train Scene.scene.json"
}

main.ts loads:

const boot = await FetchBootManifest();
const manifestUrl = import.meta.env.BASE_URL + boot.manifestPath;

Use a non-default manifest filename with levels.startManifest.

This keeps web subdirectory deploys and Tauri custom-protocol loads working without patching built JS.

Levels block

"levels": {
  "include": ["Tutorial", "Arena"],
  "start": "Tutorial"
}
FieldMeaning
includeLevel folders under public/levels/ that ship
startBoot level folder (must be in include for publish)
startManifestOptional file name if not <start>.scene.json

If levels is missing, start falls back to defaultLevel, and include defaults to every exported folder.

Edit this in the hub Levels panel or by hand. Publish scripts prune dist/levels/ to the include list after vite build.

Publish block

"publish": {
  "productName": "Playground",
  "identifier": "com.bjs.playground",
  "version": "0.1.0",
  "icon": "icon.png",
  "outputDir": "release",
  "web": { "base": "/" },
  "desktop": {
    "targetsPreset": "linux",
    "targets": "deb,appimage"
  }
}
FieldPurpose
productNameWindow title and installer product name
identifierReverse-DNS bundle id (e.g. com.studio.game)
versionVersion stamped into Tauri and zip names
iconPath to a square PNG relative to the app (or absolute)
outputDirArtifact folder — relative to the app, or absolute
web.baseVite --base for web builds (must start and end with /)
desktop.targetsTauri bundle.targets value or comma list
desktop.targetsPresetHub preset id (all, linux, windows, …)

The hub Publish panel edits these fields and writes them back to the file.

CLI commands

From the repo root:

CommandAction
npm run publish:web -- --app <name> [--base /path/]Typecheck, Vite build, prune levels, copy site to outputDir/web/, zip
npm run publish:init -- --app <name> [--force]Stamp src-tauri/ from the template

npm run publish:desktop -- --app <name>Web build (base ./) + tauri build
npm run publish:android -- --app <name>Web build + tauri android build --apk

Shared helpers: scripts/publish/config.mjs, web.mjs (exports TypecheckApp, BuildWeb, PruneLevels), icon.mjs.

Web publish

  1. Typecheck the app (tsc --noEmit).
  2. Run vite build --base <web.base or --base>.
  3. Delete level folders under dist/levels/ that are not in levels.include.
  4. Copy the pruned site to <outputDir>/web/ — that folder is the complete static site (index.html, assets/, levels/, bjs-boot.json).
  5. Zip that folder to <outputDir>/<app>-<version>-web.zip when the zip binary exists.

Upload web/ (or the zip) to any static host. Preview locally:

npx serve apps/playground/release/web

Example with a subdirectory base:

npm run publish:web -- --app playground --base /demo/

Desktop (Tauri)

Init

npm run publish:init -- --app playground

Copies scripts/publish/templates/tauri/ into apps/<name>/src-tauri/, fills product name, identifier, version, and desktop targets, then applies the icon if publish.icon is set.

Build

npm run publish:desktop -- --app playground

Steps:

  1. Sync identity and bundle.targets into tauri.conf.json.
  2. Regenerate icons if publish.icon is set.
  3. Typecheck, Vite build with base ./, prune levels.
  4. Run npx tauri build.
  5. Copy installers from src-tauri/target/release/bundle/ into outputDir.

Important: targets select installer formats. A successful build still needs the matching OS (or CI). From Linux you get Linux packages even if the preset lists msi or dmg.

Linux prerequisites

Install before the first desktop build:

sudo apt install libwebkit2gtk-4.1-dev libdbus-1-dev pkg-config \
  libayatana-appindicator3-dev librsvg2-dev

Also install a Rust toolchain (rustup). Official guide: Tauri prerequisites.

If the build fails with dbus-1.pc not found, install libdbus-1-dev.

App icon

Tauri needs a real square PNG. A 1×1 placeholder produces broken .ico / .icns files.

  1. Put a square PNG in the app (prefer 1024×1024, at least 512×512).
  2. Set publish.icon to that path (e.g. icon.png).
  3. Run npm run publish:icon -- --app <name> or click Apply icon in the hub.

scripts/publish/icon.mjs checks that the file exists, is PNG, is square, and is large enough, then runs npx tauri icon. Output goes to src-tauri/icons/.

Android

npm run publish:android -- --app playground

Requires ANDROID_HOME, an NDK (or NDK_HOME), and Java 17+. On first run the script runs tauri android init if src-tauri/gen/android/ is missing. Artifacts (.apk / .aab) copy into outputDir.

v1 ships debug-signed APKs for sideloading. For Play Store signing, follow the Tauri Android signing guide and keep the keystore out of git.

iOS is not automated here. On a Mac with Xcode, use npx tauri ios init / npx tauri ios build with the same publish identity.

Hub Publish panel

Open the hub's Publish tab. Web / Desktop / Android Build buttons sit at the top. The collapsible Settings row below them holds the identity fields: app name, version, bundle id, web base path, output folder, desktop targets, icon path.

Save settings writes babylon-project.json. Build buttons save first, then start a job. While a job runs, the panel polls logs once per second and lists files in the output folder when the job ends.
