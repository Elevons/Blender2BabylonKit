01 — Babylon Launcher

What it is

The launcher is a local control panel for one project. One Express server exposes a JSON REST API and (in development) Vite middleware for the React hub. The hub:

  • Shows the bound project and starts its Vite game server on boot
  • Edits which levels ship and which level boots first
  • Starts and stops Vite and bjs-mcp
  • Lists JSON files in per-level asset folders
  • Runs publish jobs (see Publish)

Create new apps with the CLI (npm run create). The hub does not scaffold projects.

Development (npm run hub -- --app <name> → server/dev.ts): API first, then Vite middleware for the hub.

Production (npm run launcher:start -- --app <name> → server/index.ts): API plus static dist/client/.

Default hub port: 3200. Game Vite port: babylon-project.json → dev.port (default 5173).

Project resolution

ResolveProjectDir() in server/paths.ts picks one root:

  1. --app <name> → apps/<name>/
  2. BJS_PROJECT_DIR env var
  3. Walk up from cwd for babylon-project.json

If none match, the process exits with an error. That root is PROJECT_DIR for the whole process.

Hub UI

Two tabs in the header: Develop (day-to-day) and Publish (ship builds). The header also shows the project title, version chip, and an Open game link once Vite is up.

Develop tab

Services panel

Polls GET /api/services every three seconds.

Vite Dev Server — start/stop the game in PROJECT_DIR (npm run dev). The hub also starts it automatically on launch.

bjs-mcp — build/start/stop and copy Cursor MCP config.

Docs & Tools panel

Build docs runs npm run docs:build at the repo root; View docs opens /docs/ on the hub host. Below that, links to the online Babylon node editors whose JSON you save into the asset folders.

Levels panel

Lists folders under public/levels/. For each level you set:

  • In build — include in publish artifacts
  • Boots first — start level (must be included)

Save writes the levels block in babylon-project.json. The app's Vite plugin watches that file and reloads the game. The panel footer shows the Blender Live Link export path.

Assets panel

Lists .json files in known asset folders for the selected exported level. Read-only in the UI.

Publish tab

Build buttons for Web / Desktop / Android up front; name, version, targets, icon, and output folder live behind a collapsible Settings row. See Publish.

  "title": "Playground",

Level asset folders

Assets for a level live under public/levels/<level>/. The server scans: gui/, particles/, materials/, geometry/, filters/, render-graphs/. Only .json files are listed.

Typical workflow

  1. Export from Blender into public/levels/<level>/.
  2. Run npm run hub -- --app <name>.
  3. Open the game from the hub header link.
  4. Set include/start levels in the Levels panel and save.
  5. Use Services for MCP when you author behaviors.
  6. Use Publish for web/desktop/Android artifacts.

Environment and troubleshooting

VariableDefaultEffect
LAUNCHER_PORT3200Hub listen port
BJS_PROJECT_DIR—Force project root

If port 3200 is in use: fuser -k 3200/tcp on Linux, or set LAUNCHER_PORT=3201. Free the game port the same way if Vite fails to bind.
