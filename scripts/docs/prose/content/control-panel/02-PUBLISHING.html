02 — Publishing

The Project Control Panel Publish tab builds a web copy of the current project. Choose the platform, included levels, entry level, and destination. Click Build. The server builds the project, removes excluded levels, and copies the result.

Desktop (Tauri) is listed in the UI but is not implemented yet.

Dev: jump into a level

You do not need a publish build to test a level. The Development tab lists each scene manifest. Select one and click Open Level. Click Set as Entry to save it as the project entry level. The Publish tab uses the same setting.

The app resolves the entry level in this order:

  1. ?manifest= URL query (dev jump)
  2. import.meta.env.VITE_START_LEVEL (set by Publish)
  3. The project default in main.ts

Changing the query does not restart Vite. Reload the page after you change the parameter by hand.

Publish tab flow

  1. Confirm the current project shown in the header.
  2. Open the Publish tab.
  3. Leave Platform on Web.
  4. Optional: set product title and version (written to publish-meta.json).
  5. Tick the level folders to include.
  6. Pick the Entry level from the included scene manifests. This also updates the Development tab.
  7. Type an absolute destination path (the folder is created if it does not exist).
  8. Optional: tick Encrypt / obfuscate level assets.
  9. Optional: tick Include Node.js web server.
  10. Click Build and watch the log. Click Cancel to stop a running job.

The destination is cleared of previous contents before the copy. Do not point it at the app src/ tree or the Project Control Panel tree.

What the build does

flowchart LR
  Form[Publish form] -->|POST /api/publish/app| Job[Publish job]
  Job --> Build["npm run build with VITE_START_LEVEL"]
  Build --> Filter[Remove excluded dist/levels folders]
  Filter --> Copy[Copy dist to destination]
  Copy --> Encrypt{Encrypt?}
  Encrypt -->|no| Server{Include server?}
  Encrypt -->|yes| Pack[assets.pak + pak-sw.js]
  Pack --> Server
  Server -->|no| Done[Hostable web folder]
  Server -->|yes| NodeServer[server.mjs + package.json]
  NodeServer --> Done

The job sets VITE_START_LEVEL to the chosen manifest URL while it runs npm run build --workspace game. Vite still copies every folder under public/levels/. The job then deletes folders you did not include.

Poll status with GET /api/publish/:app. Only one publish job runs per app at a time.

Encrypted asset pack

When encryption is on, every file under the output levels/ tree is packed into one assets.pak file (AES-256-GCM per file). Loose level files are removed. The build writes pak-sw.js and rewrites index.html so a small bootstrap registers the service worker before it loads the app module.

The service worker intercepts requests under /levels/, decrypts the matching pak entry, and returns the plain bytes. Engine fetch calls and Babylon loaders keep the same URLs. You do not change app or engine code for this mode.

Limits: the AES key ships inside the bundle. This slows casual asset ripping. It is not strong DRM. Encrypted builds need http:// or https://. Service workers do not run from file://.

Included Node.js server

When Include Node.js web server is on, the output includes server.mjs and package.json. The server has no npm dependencies. It serves the generated files with the correct MIME types and falls back to index.html for browser routes.

cd /path/to/published-build
npm start

The default address is http://0.0.0.0:8080. Set PORT or HOST to change it, for example PORT=3000 npm start.

How to host the output

Serve the destination folder as static files. Open the site root. Publish writes the entry level into the bundle through VITE_START_LEVEL.

For a URL subdirectory deploy (for example /demo/), the existing npm run deploy:playground -- --base /demo/ script still patches level URL prefixes. Prefer that path when you need a non-root base. The Publish tab targets a plain root-hosted folder in v1.

REST API

MethodPathDescription
GET/api/projects/:app/manifestsList { level, file, url } for every .scene.json
POST/api/publish/:appStart a publish job. Body: platform, destination, levels, startLevel, encryptAssets, includeServer, optional title/version. Returns 202 + status.
POST/api/publish/:app/cancelCancel the running publish job and kill its build process.
GET/api/publish/:appCurrent job status: phase, log, error?, destination?, progress?

Server code lives in tools/project-control-panel/server/publish.ts. The hub panel is src/hub/PublishPanel.tsx.
